# apps/web-admin — internal admin console

> Read root [`CLAUDE.md`](../../CLAUDE.md) first; Notion holds the deep docs. Package rules only below.

- Light theme + semantic tokens; calm, dense, unornamented. Design map: Notion Docs › Design. New UI takes chrome from [`src/components/admin-ui/`](./src/components/admin-ui/), never a route-local shim. `/brand` is read-only, out of the sidebar.
- Clients never touch the DB — everything via `admin-web-*` Edge Functions. The EF-invoke wrapper is the deliberate **`Result` variant** (consumer/business throw `EFError`) — keep it.
- Every config page: server seeds → client form → **WHOLE-BLOB save** to one `app_config` column, normalizer in lockstep, `dirty` gated on `loadError`. A knob nothing reads is **STAGED**.
- **A label never repeats its section heading** — Configurations › **Intake**, never "Intaker Config"; tabs too. Labels live in each route's `nav.ts` and **a rename stops there**: routes, blobs, EF names never follow. **Sidebar in product-flow order**; the set is code-defined in `CONFIGURATIONS_NAV`. **Intake** = sourcing's gate + the Intaker; `/sourcing-config` redirects. No Atlas page (spec: Docs › Atlas). **Verification** = PLACE ownership proof, **Ojo** = reading a guest's screenshot. **Memo is not a row** — it IS the chat engine, so it belongs to Discovery; it has no editor and runs on in-code defaults.
- **Discovery** (`/filters-config`) is ONE page of **TWO BOXES**: Signals · Engines. Six EARNED signals compose as `s^w`; **Promoting is not a signal**. Slotting and operator filters persist on the blob and stay enforced, with **no knobs**. Only a **wired** engine gets a ranking switch. Blob `app_config.discovery_config`, vocabulary CODE-DEFINED. Signals on Swipe.
- **Visits Config** = the LOCAL context (THE TICKET: tip chips, poll cadence, proof, send-backs, pay rails, abandonment); **Orders Config** = the REMOTE one (channels, fulfilment, per-plan quotas, eligibility). **Neither prices anything** — rates live in the Promos grid. Premium clamps up to the Free quota; the preselected tip must be a chip that exists.
- **Promos Config** (`/rewards-config`, tabs Tiers · Distribution) edits COMPONENTS; storage keeps the GRID: `standing = base + classStep + planStep`. **Tiers is SIX boxes** (paid strategy × context) — knobs first, stacking behind a disclosure. **Orders has no Class rows**, **not-wired**. `additivityError` REFUSES a grid the components can't express or whose class offsets decrease; only `google-vs-story` warns. **One Save, hoisted**; Distribution read-only. Twin: `web-business/lib/business/promos.ts`.
- `database.types.ts` is hand-copied across the web apps — regenerate from cloud, never hand-edit. CI `web-admin.yml`: lint · typecheck · build, Node 22+, path-filtered.
