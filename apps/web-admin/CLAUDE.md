# apps/web-admin — internal admin console

> Read root [`CLAUDE.md`](../../CLAUDE.md) first; Notion holds the deep docs. Package rules only below.

- Light theme + semantic tokens; calm, dense, unornamented. Design map: Notion Docs › Design. New UI takes chrome from [`src/components/admin-ui/`](./src/components/admin-ui/), never a route-local shim. `/brand` is read-only, out of the sidebar.
- Clients never touch the DB — everything via `admin-web-*` Edge Functions. The EF-invoke wrapper is the deliberate **`Result` variant** (consumer/business throw `EFError`) — keep it.
- Every config page: server seeds → client form → **WHOLE-BLOB save** to one `app_config` column, normalizer in lockstep, `dirty` gated on `loadError`. A knob nothing reads is **STAGED**; unenforced config is a bug.
- **A label never repeats its section heading** — Configurations › **Intake**, never "Intaker Config"; tabs too. Labels live in each route's `nav.ts` and **a rename stops there**: routes, blobs, EF names never follow. **Sidebar in product-flow order** — the eight the quickstart names, plus **Access**. No Atlas page (spec: Docs › Atlas). **Verification** = PLACE ownership proof, **Ojo** = reading a guest's screenshot. **Memo is not a row** — it IS the chat engine, so it belongs to Discovery; it has no editor and runs on in-code defaults.
- **Discovery** (`/filters-config`) is ONE flat page of **FOUR BOXES, never tabs**: Signals · Bought slots · Filters · Engines. Six EARNED signals compose as `s^w`; **Promoting is not one** — money buys a POSITION, never a score. **A SIGNAL DEMOTES, A FILTER EXCLUDES**: filters are operator pool policy (query predicates), NOT the guest surface MESITA-1183 killed. Only a **wired** engine gets a knob. Blob `app_config.discovery_config`, vocabulary CODE-DEFINED. Signals on Swipe, filters on Swipe + Map.
- **Visits Config** = the LOCAL context (THE TICKET: tip chips, poll cadence, proof, send-backs, pay rails, abandonment); **Orders Config** = the REMOTE one (channels, fulfilment, per-plan quotas, eligibility). **Neither prices anything** — rates live in the Promos grid. Premium clamps up to the Free quota; the preselected tip must be a chip that exists.
- **Promos Config** (`/rewards-config`, tabs Tiers · Distribution) edits COMPONENTS; storage keeps the GRID: `standing = base + classStep + planStep`. **Tiers is SIX boxes, one per (paid strategy × context)** — a place picks one strategy, so its column IS its whole program. **Orders has no Class rows**, **parked**. **Bonuses are per strategy AND per context**, fanned out on read. `additivityError` REFUSES a grid not expressible as components, or whose class offsets decrease, so the ladder cannot invert; only `google-vs-story` warns. **One Save, hoisted to the layout**; Distribution read-only. Twin: `web-business/lib/business/promos.ts`.
- `database.types.ts` is hand-copied across the web apps — regenerate from cloud, never hand-edit. CI `web-admin.yml`: lint · typecheck · build, Node 22+, path-filtered.
