# apps/web-admin — internal admin console

> Monorepo-wide rules: root [`CLAUDE.md`](../../CLAUDE.md) (the quickstart) — read it first. This file adds only package-specific rules.

- Light theme + semantic tokens; calm and high-density — don't ornament. Design map: Notion Product Rules §F (web-admin). Brand reference (marks, pink ramp, lockup rules) is the `/brand` page — read-only, rendered from shipped tokens, reachable by URL and absent from the sidebar; its source is `assets/brand/brand.json`. Shared chrome: [`src/components/admin-ui/`](./src/components/admin-ui/) (`config` · `manage`). New admin UI imports from there; do not grow the route-local shims.
- Clients never call the DB — everything via `admin-web-*` Edge Functions. The EF-invoke wrapper here is the deliberate **`Result` variant** (consumer/business throw `EFError`) — keep the divergence; dedupe only the plumbing beneath it.
- "**Atlas**" is legacy branding for the place-intelligence subsystem (why `atlas-*` routes / `atlas_*` columns persist) — the Enricher is the pipeline. **Atlas** (`/atlas-config`, profile-spec) and **Enricher** (`/enricher-config`, pipeline behavior) are separate sidebar parents — never treat them as one page.
- **A sidebar label never repeats its section heading**: the group says Configurations, so the item is **Atlas**, not "Atlas Config". Labels live in each route's `nav.ts`; [`Sidebar.tsx`](./src/components/Sidebar.tsx) is their only consumer. The desktop rail collapses to icons; that choice rides the `admin_sidebar_collapsed` cookie, read by the server layout so the first frame paints at the right width.
- **Configurations are ordered by product flow, not alphabetically**: Admin · Models · Sourcing · Atlas · Enricher · Verification · **Ojo** · Promos · Memo · Reservations. Two "is this real?" pages that are NOT the same thing: **Verification** (`/verification-config`) governs PLACE ownership proof; **Ojo** (`/ojo-config`) governs the proof-verification engine that reads a guest's story/review screenshot — every Ojo knob is **staged** (live blob, no reader) until the engine ships, and the console must keep saying so. **Promos** keeps the `/rewards-config` route on purpose (rename is copy-only); its tabs are Config + Distribution.
- **Promos Config is v11 — context first, then two identity axes:** **Visits** prices `class × plan` (8 rows/strategy); **Orders** drops class, prices plan alone, and is **parked** — knobs save, nothing reads them, and the console says so;  classes `bronze < silver < gold < diamond` (never purchasable), plans `free`/`premium` (never shown to a place). The DB still stores the retired `standard < influencer < premium < aura`, which `identityForClassKey` maps onto the v11 axes where **`premium` is a PLAN**; both live until the table is renamed. The page REPORTS ladder violations, never auto-corrects. Twin in lockstep: `apps/web-business/src/lib/business/promos.ts`. Top-rung roster: `/aura-consumers`.
- `database.types.ts` is hand-copied across the web apps (`apps/*/src`) — regenerate from cloud, don't hand-edit.
- CI: `web-admin.yml` — lint · typecheck · build (Node 22+), path-filtered to `apps/web-admin/**`.
