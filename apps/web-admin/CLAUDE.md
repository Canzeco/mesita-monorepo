# apps/web-admin — internal admin console

> Read root [`CLAUDE.md`](../../CLAUDE.md) first; Notion holds the deep docs. Package rules only below.

- Light theme + semantic tokens. Map: Notion Docs › Design. New UI takes chrome from [`src/components/admin-ui/`](./src/components/admin-ui/), never a route-local shim. `/brand` is unlisted.
- Clients never touch the DB — all via `admin-web-*` EFs. EF-invoke is the **`Result` variant**.
- Every config page: server seeds → client form → **WHOLE-BLOB save** to one `app_config` column, normalizer in lockstep, `dirty` gated on `loadError`. A knob nothing reads is **STAGED**.
- **A label never repeats its section heading** — Configurations › **Creation**. Labels live in `nav.ts`; routes, blobs, EF names never follow. Sidebar: `CONFIGURATIONS_NAV` = Models · Atlas · Creation · Enrichment · Discovery · Reservations. Multiple Places writes in three boxes, **Create · Enrich · Edit** (List · Unlist · Delete; never an Edit button) — buttons repeat box names, except Enrich's Quick and Full. **"Crenup" BANNED.** Enricher: Create 0·1·7·8, Enrich **1–8**. Delete archives, reversible only by hand. **Creation** holds the two Create-on-open switches (consumer app · admin app): opening a Google-only result's full profile is the one thing that mints a place; an explicit Create is never gated. **No verification, partnership, rewards or payments** (MVP). Search eligibility: Discovery › Map; Places: one query/line. **Ojo** = guest screenshot. Memo powers Discovery chat; Chat writes `discovery_config.chat.prompt`. **Models** (`/models-config`) = four AI jobs: Memo's `models_config` model + Enricher writing/photos/search (`enrichment_config`, two tiers); Creation links there.
- **Discovery** (`/filters-config`): nouns **Mode** · **Source**; four subpages mount together. **Sources**: seven — 3 Google · Mesita Name · Nearby · Catalog · Social Catalog (no engine). **Modes**: Word · Map · Catalog · Chat · Favorites; Catalog carries the read-only Feed **Rails** list. A mode weights the signals it ranks (Catalog's four, Map's lineup); Word, Chat, Favorites do not rank. **Signals**: Name · Description · Family · Proximity (Max km) · Timing (Closed floor) · Enriched · Popularity · Randomness; each but Description draws a graphic computed by `admin-web-preview-signals`, no inputs to type. **Matrix**: fixed mode×source grid. Floors stay in the source that owns them; family membership lives on Atlas.
- **MVP First Stage rail:** Account · Manage · Configurations · Testing (**Billing** `/billing-test` · **Logs** `/logs`). Alerts and every Second Stage page (Visits, Rewards, Ojo, Orders, Payments, Diamond) are deleted, routes and config sections. Manage: **Multiple Places** (`/manage-multiple`, bulk) · **Single Place** (`/manage-single`: Find, then `/[id]/{profile,reviews,preview,admin}` — `FIRST_STAGE_TABS` in `[id]/access.ts`; Reviews reloads Google, Instagram and Facebook and is not part of Enrich; Preview renders the saved place through `packages/place-profile`, the consumer place screen's module). **"promo"/"membership" BANNED.**
- `database.types.ts` is hand-copied across web apps — regenerate from cloud, never hand-edit. CI `web-admin.yml`: lint · typecheck · test · build, path-filtered.
