- Light theme + semantic tokens; calm and high-density — don't ornament. Design map: Notion Product Rules §F. New UI imports shared chrome from [`src/components/admin-ui/`](./src/components/admin-ui/) (`config` · `manage`); don't grow the route-local shims. `/brand` is a read-only, sidebar-less reference generated from `assets/brand/brand.json`.
- Clients never call the DB — everything via `admin-web-*` Edge Functions. The EF-invoke wrapper is the deliberate **`Result` variant** (consumer/business throw `EFError`); keep the divergence, dedupe only the plumbing beneath it.
- **Atlas** (`/atlas-config`, profile-spec) and **Enricher** (`/enricher-config`, pipeline behavior) are separate sidebar parents — never merge them.
- **A sidebar label never repeats its section heading**: the group says Configurations, so the item is **Atlas**, not "Atlas Config". The rail collapses to icons via the `admin_sidebar_collapsed` cookie, read server-side so the first frame paints at the right width.
- **Configurations are ordered by product flow, not alphabetically**: Admin · Models · Sourcing · Atlas · Enricher · Verification · Ojo · Filters · Promos · Memo · Reservations. **Verification** (`/verification-config`) governs PLACE ownership proof; **Ojo** (`/ojo-config`) governs the engine reading a guest's story/review screenshot — not the same page, and every Ojo knob is **staged** until that engine ships.
- **Filters Config** (`/filters-config`): **General** carries the law — which of the six modules exist (Context · Where · Distance · When · What · Random), defaults, bounds, store behavior — and six surface tabs (**Swipe · Catalog · Chat · Social · Map · Search**) inherit or override it. **`inherit` TRACKS General**; General's master switch beats a surface saying `on`. Blob `app_settings.filters_config.v1`, WHOLE-BLOB write, EF normalizer in lockstep. Every knob is **`not-wired`** (the consumer sheet runs code defaults); Catalog · Chat · Social are also **surface parked**.
- **Promos Config is v11 — context first, then two identity axes:** **Visits** prices `class × plan`; **Orders** drops class, prices plan alone, and is **parked** — knobs save, nothing reads them, and the console says so. Classes `bronze < silver < gold < diamond` (never purchasable), plans `free`/`premium` (never shown to a place). The DB still stores `standard < influencer < premium < aura`, which `identityForClassKey` maps onto the v11 axes where **`premium` is a PLAN**. Route stays `/rewards-config`; tabs are Config + Distribution. Twin in lockstep: `apps/web-business/src/lib/business/promos.ts`. Top rung: `/aura-consumers`.
- **Filters and Promos REPORT contradictions, never auto-correct.**
- `database.types.ts` is hand-copied across the web apps (`apps/*/src`) — regenerate from cloud, don't hand-edit.
