# apps/web-consumer — consumer app (consumer.mesita.ai)

> Monorepo-wide rules: root [`CLAUDE.md`](../../CLAUDE.md) (the quickstart) — read it first. This file adds only package-specific rules.

- **Light theme + semantic tokens only** (`bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`) — never `bg-zinc-900`/`text-white` on app surfaces. Consumer surfaces read **premium**: branded gradients on hero/promo, tinted icon circles, differentiated chips. Wireframe stacks are a regression. Design map: Notion Product Rules §F.
- **Overlay & loading primitives are mandatory:** route modals via `SlideOverShell`/`BottomSheetShell` mounted from the segment `layout.tsx` (never `page.tsx`); state overlays via `LocalSheet`/`LocalDialog` (never `fixed inset-0`); loading via `Spinner`/`Skeleton`. Z-scale: BottomNav 40 · @modal 120 · local 130 · Toaster 140. Lint baseline = **0**.
- **Parked blocks are not dead code.** Unused components and mock data await un-park — check for a parking comment, a coming-soon route, or a live `@modal` before deleting. `CatalogGrid` works today; un-parking Catalog is `soon: false` plus the page body.
- **Five bottom tabs — Home · Search · Visit · Inbox · Me**, plain labels only. Canonical routes and every legacy redirect: `src/lib/consumer-route-contract.ts`, drift-guarded against the mobile copy.
- **Inbox = one container, four sections, fixed order: Visits · Orders · Reservations · Notifications** (`/inbox/{...}`; bare `/inbox` → visits). **The order is load-bearing** and a pinned test asserts it. The icon is an inbox tray, not a calendar. **Visits** reads the same `useConsumerTickets` hook the wallet does — no second source of truth. **Orders** is parked with no table, EF or type anywhere in the stack; it renders a coming state and stays visible. **Reservations** is ONE feed: upcoming soonest-first, then past most-recent-first. **Notifications is YOUR activity only** — global activity lives at Home › Social. The reservations LIST lives here; the **detail stays at `/reservation/[id]`**.
- **The third tab is Visit** (QR icon) — never "Rewards", never "Pay": `checkout` means Stripe here. Its route is still `/rewards/*`.
- **The wallet is a searchbar over a bare place list** — no tabs, no switcher, no ticket lists, **no steps rail**; keep the "Your visits live in Inbox" link. The header reuses `search/SearchBar` (its filter affordance is optional); `PlacePickList` filters the ≤100 loaded rows client-side on name · zone · category. One tap creates the ticket at the `base` rung and opens **THE TICKET**, a full-page four-step modal at `/rewards/ticket/[id]` (reward → task → QR → results); a place with a live ticket re-opens it instead of 409-ing. The rung is picked inside the modal and re-prices upward. Rates always come from `consumer-web-get-reward-quote`, never a static ladder.
- **Proofs are screenshots:** story and Google-review submissions upload client-side to the `ticket-proofs` bucket (RLS: own folder) and persist the URL. The declaration verifies; nothing reads the image yet (Ojo, staged).
- **Home hub = five modes; only Swipe and Favorites are FUNCTIONAL.** Catalog · Chat · Social are real routes that redirect to swipe, pill opens a coming-soon dialog. All five pills stay visible and fit `max-w-md` at rest; `HomeModeNav` stays a `scrollbar-hide` scroller as the large-text fallback, not the resting state. The AI pill reads **Chat**; **Don Memo** is the persona inside it (`/home/ai`, Spanish-first — app chrome stays English).
- **Consumers hold doors, not a slot.** Rank order `standard ‹ influencer ‹ premium ‹ aura`; the slot caches the highest-ranked open door. Me is flat (`/me`); Class and Settings are modals. Favorites = localStorage (`useSavedPlaces()`). Referral = `/share`.
- Clients never call the DB — everything via `consumer-web-*` Edge Functions.
- CI: `web-consumer.yml` — lint · typecheck · test (vitest: route contract + middleware gate) · build, all blocking (Node 22+), path-filtered to `apps/web-consumer/**`.
