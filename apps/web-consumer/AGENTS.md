# apps/web-consumer — consumer app (consumer.mesita.ai)

- **Light theme + semantic tokens only** (`bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`) — never `bg-zinc-900`/`text-white` on app surfaces.
- **Consumer surfaces must read premium:** branded gradients on hero/promo, tinted icon circles, differentiated chip colors, calibrated copy. Plain wireframe stacks are a regression.
- **Parked building blocks:** unused feature components + mock data are deliberately parked for later un-park — knip/ts-prune "unused" here is usually NOT dead code. Check for a parking comment, a "coming soon" route, or a live `@modal` before deleting.
- **Overlay & loading primitives are mandatory:** route modals via `SlideOverShell`/`BottomSheetShell` mounted from the segment `layout.tsx` (never `page.tsx`); state overlays via `LocalSheet`/`LocalDialog` (never `fixed inset-0` / bare `absolute`); loading via `Spinner`/`Skeleton`. Z-scale: BottomNav 40 · @modal 120 · local 130 · Toaster 140. Lint baseline = **0**.
- Five bottom tabs (Home/Search/Rewards/**Inbox**/Profile). The Inbox tab is the **reservations surface renamed at the label only** (2026-08-15) — a container for **Reservations · Orders · Notifications**, so it isn't named after any one function (nor after the mechanism: "Agent" was rejected because a future direct integration would falsify it). Routes stay `/reservations` + `/reservation/[id]` and a booking is still a *reservation*; only the tab label and section-level copy say Inbox. **Known half-state:** notifications still live at their own `/inbox/mine` + `/inbox/global`, reached from Me — so "Inbox" currently names two different things. Folding them into the tab is the outstanding half. Consumers use the **doors model** (MESITA-972 / segments v6): Standard / Premium / Influencer / Aura — a consumer can hold several doors open at once; the class **slot** is a cache of the highest-rank open door (`magnetic` and `free` are retired keys) on the flat **`/me`** page — Class & Settings open as modals, not sub-routes; legacy `/me/class`, `/me/settings`, `/me/plan`, and `/profile` all redirect to `/me`. Favorites = localStorage (`useSavedPlaces()`), not an EF. Referral page = `/share` (`/invite` redirects). AI persona = **Don Memo** (`/home/ai`, parked — redirects to `/home/swipe` until un-parked; Spanish-first — only the AI's own messages are Spanish). Home hub = five modes: **Swipe** · **Favorites** live; **Catalog** (`/home/catalog`) · **Memo** · **Social** parked (real routes that redirect to swipe; the pill opens a coming-soon dialog). Canonical route map + legacy redirect table live in `src/lib/consumer-route-contract.ts` (drift-guarded with the mobile copy).
- **Rewards wallet = two tabs + THE TICKET** (MESITA-1024/1026/1029/1033). **New** is a bare place list and nothing else — no live ticket pinned above it; **History** holds the rest (the Pending bucket is dead). **One tap on a place creates the ticket** at the `base` rung (no pre-create wizard — `TicketWizard` is gone) and opens **THE TICKET**, a full-page four-step modal at `/rewards/ticket/[id]` (reward → task → QR → results); tapping a place that already has a live ticket re-opens it instead of 409-ing. The rung is picked *inside* the modal and re-prices upward, so the QR works from the first frame. Rates are always quoted from the engine (`consumer-web-get-reward-quote`), never from a static ladder.
