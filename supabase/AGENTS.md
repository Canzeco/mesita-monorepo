- **`profiles` is `SECURITY INVOKER`.** Consumer browse (`consumer-web-list-places`) reads it with the ANON key, RLS the single source of truth, so the view MUST run as the caller: `places_select_public_visible` gates it to `state ∈ {active,lead}` + `content_state ∈ {ready,generating,queued,failed}`; service-role EFs bypass RLS and see every row. **INVARIANT: any `create or replace view public.profiles` MUST include `with (security_invoker = true)`** — dropping it silently reopens the leak. `rls_enabled_no_policy` tables are the deliberate EF-only lockdown; adding policies OPENS access. Client roles hold no privileges on EF-only tables and SELECT-only on browse/vocabulary tables.
