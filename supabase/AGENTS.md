- **`projects_view` is `SECURITY INVOKER`.** Consumer browse (`consumer-web-list-places`) reads it with the ANON key and relies on RLS as the single source of truth, so the view MUST run as the caller: `projects_select_public_visible` gates it to `status ∈ {active,lead}` + `content_status ∈ {ready,generating,queued,failed}`; service-role EFs bypass RLS and see every row. **INVARIANT: any `create or replace view public.projects_view` MUST include `with (security_invoker = true)`** — dropping it silently reopens the leak. `rls_enabled_no_policy` tables are the deliberate EF-only lockdown; adding policies OPENS access. Client roles hold no privileges on EF-only tables and SELECT-only on browse/vocabulary tables.
- **The bill engine is ADDITIVE.** When `app_settings.rewards_config.v10` exists, `_shared/rewards-config.ts::resolveTicketRate` pays `base(strategy × class) + welcome + each earned bonus` (story with an Influencer override, plus google and mesita), clamped to 100 and applied to the first cap-pesos. Best-of over the v13 grid survives ONLY as the no-v10 fallback; `reward_rules` is a frozen mirror written on save, not a pricing source. Welcome grants on the first verified ticket at the place, decoupled from the Google review. Cap: `v10.cap` (200/500/1000, default 500) is the platform fallback; the per-place knob is `projects.monthly_promo_cap`. Strategies are `zero`/`conservative`/`aggressive`.
- **`places.name` is a GENERATED column** — `coalesce(mesita_name, google_name)`. The identity spine is the immutable `google_place_id`; `google_name` is the Enricher's cached observation, `mesita_name` the operator override (NULL ⇒ follow Google). **No EF may write `name`** — Postgres rejects it (428C9) and `_shared/place-name-writes.test.ts` guards it.
- Realtime is for ticket workflows only. **`admin_reset_database` discovers every `public` base table at run time and truncates all except rows in `public.admin_reset_preserve`** — a new operational table is wiped by default; a table that must SURVIVE is an `INSERT` into that registry, never a copy-paste into the function body. Required survivors (`app_settings`, `super_admins`, `reward_rules`, vocabularies) are asserted before truncate, so an emptied registry aborts instead of wiping blind. Storage is purged over the Storage API, never by deleting `storage.objects` rows.
- **Enricher ops (process, not agent):** cron EF pipeline `supabase-cron-enrich-place-{research,analysis,contents}` over `place_research`.
