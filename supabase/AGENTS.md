- **`profiles` is `SECURITY INVOKER`.** Consumer browse (`consumer-web-list-places`) reads it with the ANON key, RLS the single source of truth, so the view MUST run as the caller: `places_select_public_visible` gates it to `state = active` + `content_state ∈ {ready,generating,failed}`; service-role EFs bypass RLS and see every row. **INVARIANT: any `create or replace view public.profiles` MUST include `with (security_invoker = true)`** — dropping it silently reopens the leak. `rls_enabled_no_policy` tables are the deliberate EF-only lockdown; adding policies OPENS access. - **`place_profiles.name` is a GENERATED column** — `coalesce(mesita_name, google_name)`. - **`admin_reset_database` discovers every `public` base table at run time and truncates all except rows in `public.admin_reset_preserve`** — a new operational table is wiped by default; a table that must SURVIVE is an `INSERT` into that registry, never a copy-paste into the function body. Required survivors (`app_config`, `super_admins`, vocabularies) are asserted before truncate, so an emptied registry aborts instead of wiping blind. - **Enricher ops:** a direct call starts Render. One place runs `enrich-single-place`. Many places run `enrich-multiple-places` once, and Render decides how many run at once. `admin-web-enrich-place` is that call. When Render accepts the run, the proxy sets `content_state = generating` and returns. That is enriching. The old poller is paused and does not start a run. Render gathers the profile and writes it once. That write is `enricher-edgefunc-write-place`: the Google spine, the official links (Google's own, plus the ones Firecrawl sourced and the Enrichment-page Resolver kept), the price level, hours, reviews, a description, the gallery that page asked for, and the search vectors, with `content_state = ready`, in one `profiles` update, or no write. That is enriched. A failed task sends `stop` before it exits. The update matches only while generating. The parent stops every unfinished place.
