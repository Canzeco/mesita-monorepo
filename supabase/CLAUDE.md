# supabase — DB · RLS · Edge Functions (source of truth)

> Monorepo-wide rules: root [`CLAUDE.md`](../CLAUDE.md) (the quickstart) — read it first. This file adds only package-specific rules.

- **New here? Read [`ARCHITECTURE.md`](./ARCHITECTURE.md)** — the system map (audiences, topology, EF caller taxonomy, data layer, the Enricher pipeline, agents, billing).
- Run every `supabase` command from **this package** (`<repo>/supabase` — CLI config lives at `supabase/config.toml` inside it). All Supabase files live only here — kill stray `supabase/` config stubs anywhere else in the monorepo (a stray stub links against a divergent migration ledger).
- **EF name = the ACL:** `actor-origin-verb-noun`, exactly one caller per endpoint from the closed set. `_shared/` holds shared code (internal naming free-form). Only `supabase-edgefunc-*` endpoints accept the internal caller; the origin propagates via `X-Internal-Caller`.
- **Mirror + verify:** every cloud change (schema/RLS/EF) mirrors into this package the same session. After any EF deploy, confirm cloud == repo (`get_edge_function`) — a smoke-test stub once silently clobbered prod.
- **Migrations:** MCP `apply_migration` stamps its own server-side timestamp ≠ the repo filename — reconcile `schema_migrations` after, or the next `db push` re-runs those files. Prod EF deploys + security-sensitive DDL are gated by the harness classifier — attempt a `supabase …` command once cleanly, else hand off a `deploy:` step.
- **`projects_view` is `SECURITY INVOKER`** (MESITA-599 — flipped from DEFINER; clears advisor 0010). Consumer browse (`consumer-web-list-places`) reads it with the ANON key and relies on RLS as the single source of truth, so the view MUST run as the caller: `projects_select_public_visible` gates it to `status ∈ {active,lead}` + `content_status ∈ {ready,generating,queued,failed}` (enriching places stay browsable); service-role EFs bypass RLS and see every row. **INVARIANT: any `create or replace view public.projects_view` MUST include `with (security_invoker = true)`** — dropping it silently reopens the leak (this is exactly how `20260712040000` regressed it). `rls_enabled_no_policy` tables are still the deliberate EF-only lockdown (adding policies OPENS access).
- Supabase Realtime is for ticket workflows only. **`admin_reset_database` discovers every `public` base table at run time and truncates all except rows in `public.admin_reset_preserve`** (20260805221843) — a new operational table is wiped by default; a table that must SURVIVE a reset (admin configs / vocabulary) is an `INSERT` into that registry, never a copy-paste into the function body. Required survivors (`app_settings`, `super_admins`, `reward_rules`, …) are asserted before truncate so an emptied registry aborts instead of wiping blind. Storage is purged by the EF over the Storage API, never by deleting `storage.objects` rows (that strands the files).
- **Enricher ops (process, not agent):** cron EF pipeline `supabase-cron-enrich-place-{research,analysis,contents}` over `place_research`. Canonical stage order (code SoT — `enrich-pipeline.ts`; ignore any MD that disagrees): `research → analysis → contents → done`. Drivers: pg_cron job `run-place-enrichment-stages` (primary) + `admin-web-enrich-place` modes `full|analysis|contents` (prefer cheap modes when `gathered`/`analysis` exist — `full` burns Apify/Perplexity/Firecrawl). Judge by DB effects (`gathered->sources`, places fields, media), never green beacons alone. Spend kill switch: `select cron.unschedule('run-place-enrichment-stages');` (re-arm via the place_research pipeline migration / `cron.schedule` for that job name).
- CI: `supabase.yml` — deno lint · test (Deno toolchain, no Node build), path-filtered to `supabase/**`. Instruction-file sync check = root `rules.yml`.
